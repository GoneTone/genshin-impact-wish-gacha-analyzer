## 一、目的

照鳴潮版的做法，讓手機直向、橫向的介面更好用，同時兼顧電腦版，最後實測滑動流暢度。鳴潮版的示意圖使用者 2026-11-07 已確認（https://claude.ai/artifact/TeMxuPicwtkHjezNCM7nsL ，12 個畫面），原神版外觀以它為準，不重畫。

鳴潮 spec 列了 26 項目標，分成：外殼（底部列、側欄連結、橫向標題列捲動收起）、數字卡並排、精簡圓餅、紀錄列表（篩選一列、跳頁對話框、換頁捲回表頭、手機橫向用卡片）、空資料提示嵌入按鈕圖案、物品詳情（左右滑動、頁點、雙欄、左欄單一捲動區）、帳號管理（每個帳號一列＋⋮ 選單），以及驗收期間加的對話框右上角 ✕。細節以鳴潮 spec 與各 commit 為準，本文件只寫原神的範圍與差異。

**不在這次範圍（使用者 2026-11-20 選 A，拆成子專案 9b）**：移植筆記第 47、48 節的啟動畫面配合主題（`c8307a3`、`a0c9180`）、系統「應用程式語言」雙向同步（`d5383ea`）。

## 三、目標／非目標／反目標

**目標**：鳴潮 spec 目標 1～26，加上對話框右上角 ✕，全部套用到原神，含頌願頁（共用 `BannerPage`）。

**非目標**：和鳴潮相同（電腦版外殼、電腦版紀錄表、電腦版圓餅不變；不加新功能）。另外：

**反目標**：鳴潮 spec 的反目標全部適用（核心語言或放大字級下溢出、橫向標題列收起後找不回來、滑動切換與捲動或放大互相干擾、資料或功能消失），另外：
- 子專案 8 的成果退步：按需建構、keep-alive、五星一覽逐列、電腦版整頁預建、時間軸與鳴潮對齊的寫法。

## 四、原神特有的部分（必須保留）

- **頌願**：綜合頁「祈願／頌願」兩段（`_OverviewSection`）都套用數字卡並排、精簡圓餅等規則；頌願頁共用 `BannerPage`，跟卡池頁一起改。頌願段沒有五星一覽。
- **社群連結列**（`team_links_bar.dart`）：原神是 4 個圖示（Facebook、Discord、LINE、GitHub）加團隊名稱「原神資訊站 Genshin Impact Info」，鳴潮是 3 個圖示（沒有 LINE）加「旋風之音 GoneTone」。原神整列比鳴潮寬很多（粗估 360dp 對 250dp），側欄的放法見 4.1。
- **物品詳情**：原神是 HoYoWiki 內容（描述、標籤、衣裝、圖片清單、GIF）與「在 HoYoWiki 查看」，鳴潮是 encore.moe 與立繪擷取。版面規則（左右滑動、頁點、箭頭點擊範圍 ≥ 44、手機橫向與電腦版雙欄、左欄單一捲動區與底部漸層、⋮ 選單保留）照搬；內容區塊、圖片載入與快取邏輯、GIF 處理維持原神現狀。原神沒有立繪擷取，相關部分不移植（審查確認範圍內改詳情的 commit 只在註解提到立繪，沒有程式依賴）。原神的衣裝說明（`imageDesc`）在單欄時沒有鳴潮那樣的 96dp 高度上限，所以 `ce78d54` 的捲動提示在原神單欄只作用在簡介區塊；不替衣裝說明新增上限（維持原神現狀）。現有結構已和鳴潮相近（頂部標頭、`maxHeight: 120` 的說明、手機橫向雙欄 `_twoColumnDetailsWidth`），差異約 780 行，主要是內容不同。
- **術語**：「喚取」→「祈願」；「紀錄」→「記錄」（例如「紀錄列表」→原神既有用字）。字串 key 以原神 ARB 現有的為準。
- **數字卡**：原神卡池頁的保底門檻與次保底規則依原神（例如武器池 80、集錄池），「沒有次保底的卡池，總抽數獨佔一列」依原神卡池實際判斷。
- **空資料提示**：原神現有文案「Click "Update" in the top right to start」改成 `{icon}` 佔位符版本。

### 4.1 側欄社群連結列（偏離鳴潮，使用者 2026-11-20 決定）

鳴潮在手機（直向與橫向）把社群連結從底部列拿掉，改放在側欄最下方：整列（圖示＋分隔線＋團隊名稱）用 `FittedBox` 放不下時等比例縮小。原神整列約 360dp，側欄約 304dp，照搬會縮到 0.8 倍以下，圖示點擊範圍小於 44dp，所以原神在側欄改成**兩行**：

- 第一行：4 個圖示，用 `TeamLinksBar` 既有的手機尺寸（`compact`，點擊範圍 48dp，4 個共 192dp，放得下），不縮小（**我的判斷**：電腦版尺寸只有 40×32dp，達不到 44dp）。
- 第二行：團隊名稱「原神資訊站 Genshin Impact Info」，空間不夠時換行，不縮小、不截斷；兩行之間不放分隔線。
- 兩行照 `2912431` 的精神各自在可見內容間置中（圖示按鈕左右自帶的空白對稱，不需要 `iconInset` 補償）。
- 其他行為照鳴潮：手機（直向與橫向）底部列不放社群連結、只在側欄出現；電腦版不用滑出式側欄，底部列維持原神現狀的一行。
- 共用 `team_links_bar.dart` 既有的圖示與名稱連結元件，只在側欄改成上下排列，不另寫一套連結清單。

## 五、做法細節

- **ARB**：新字串與改成 `{icon}` 的字串，加在**全部 9 份已翻譯 ARB**（zh、zh_Hans、en、es、fr、ja、pt_BR、th、vi），空殼不動（**我的判斷**：鳴潮當時只改 4 份核心，原神依「新 key 只加在已翻譯 ARB」的慣例）。先寫 `app_zh.arb`，再以中文為準翻其他語言；有鳴潮同 key 翻譯的語言參考鳴潮 master，術語換成原神的。省略號半形 `...`。
- **差異大的檔案**（`gacha_item_detail_dialog.dart`、`app_shell.dart`、`overview_page.dart`、`banner_page.dart`、`rarity_pie.dart`、`item_type_pie.dart`、`share_progress_dialog.dart`、`update_progress_dialog.dart`、`settings.dart`，以及測試 `phone_layout_pages_test.dart`、`app_shell_test.dart`）：先比對原神與鳴潮移植前（`f720f7b`）的差異，再套用鳴潮的改法。遇到鳴潮的改法在原神行不通、或需要改變原神特有內容時，停下來回報，不自行改寫（使用者原則：偏離姐妹專案前先問）。
- **子專案 8 的狀態保留**：鳴潮 `b32a24d`（篩選列 keep-alive 在 `LayoutBuilder` 內）、`b8cd4a8`（卡池頁只因高度改變不整頁重建）照搬，確保按需建構與 keep-alive 不退步。
- **log**：照搬鳴潮新增的 log（例如 `adfaf9c` 別名未變不記錄），英文、不記敏感資料。
- **CLAUDE.md**：在「Dialog 一律用 `AppDialog`」那條補上 `xl` 尺寸與預設右上角 ✕ 的說明，內容照鳴潮 `5afe5e3`，換成原神的用語。

- 照搬鳴潮在這些 commit 新增的測試（鳴潮 spec「驗收」列的每一項），改寫到原神的測試 helper；既有斷言不可刪減。

**外觀與操作（模擬器，使用者 2026-11-20 同意手機部分改用模擬器）**

**滑動流暢度（實機，要使用者同意才動手機）**

- 模擬器的畫面是軟體模擬，量出來的準時率沒有參考價值，所以在 ROG Phone 上裝 **profile 版**，用 `tool/measure_frame_pacing.sh`（子專案 8 已搬入）量綜合頁與卡池頁（角色活動、武器活動、頌願）的慣性滑動準時率，直向與橫向各量一次。目標 ≥ 95%（鳴潮同標準），並記錄靜止時是否出幀。
- 鳴潮是在開著無障礙服務的條件下量的，原神照同樣條件，量之前先記下手機目前的無障礙服務狀態，不額外開關。
- 測完依記憶「手機測完要真的還原」收尾（轉向、snapshot helper 等）。手機上的原神 App 是 debug 版與朋友帳號，profile 版覆蓋安裝會保留資料。
